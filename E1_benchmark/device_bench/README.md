# Device Bench — 기기 일반화 측정 프로토콜

논문의 "기기 일반화" 표를 채우기 위한 표준화된 기기별 벤치마크. 현재 실기기 증거가 iPhone 1대(카카오톡 웹뷰)뿐이고, E1 은 랜드마크 주입 방식이라 기기 편차를 말하지 못한다는 한계(원고 Limitation 5)를 보강한다.

## 프로토콜 (기기당 ~3분)

1. 대상 기기에서 **https://wansukchoi-kbu-squat.vercel.app/devicebench.html** 열기
   (앱 헤더 📚 자료 → 📱 기기 벤치마크로도 진입 가능)
2. 페이지 안내대로 5단계 실행:
   ① 환경 프로브(자동) ② 저장소(자동) ③ TTS 청취 확인
   ④ pitch 앵커 2점 — **벽에 수직(0°) / 책상 평면(−90°)**, 도구 불필요
   ⑤ 카메라 30초 — 측면, 처음 8초 정지 → 스쿼트 5회
3. 기기 라벨 입력 (예: `iPhone 15 / Safari`) → **JSON 다운로드**
4. JSON 을 이 디렉터리에 넣고:

```bash
node device_bench_analyze.cjs
```

## 권장 기기 매트릭스 (4~6대)

| 축 | 최소 구성 |
|---|---|
| iOS | iPhone 최신 + 구형 1대 (Safari, 카카오톡 인앱 각각) |
| Android | 갤럭시 플래그십 + 중저가 1대 (Chrome, Samsung Internet) |
| 저성능 확인 | 가장 오래된 가용 기기 — fps 하한 데이터가 가장 값지다 |

## 분석기가 계산하는 것

- **fps → 깊이 저평가 투영**: 각 기기의 실측 fps(중앙값·느린10%)에서 배포 코드의 EMA(`smooth`, 추출 코어 그대로)가 스쿼트 깊이를 몇 도 저평가하는지 — Tier 0 T0.2 방법의 임의 fps 재계산 (보간 아님)
- pitch 앵커 오차 최대치, 정지 시 무릎각 지터, TTS 한국어 가용성, 저장소 동작
- `device_bench_summary.{json,csv}` — 원고 표에 그대로 옮길 수 있는 형태

## 주장 위생

- 이 벤치마크는 **기기·브라우저 환경의 측정 신뢰성**을 말한다. 인체 측정 타당도는 여전히 Tier 2 (mocap 대조)와 IRB 검증연구의 몫이다.
- 깊이 편향 투영은 "이 fps 라면 EMA 가 이만큼 저평가한다"는 **결정론적 필터 특성**이지, 해당 기기에서의 실측 각도 오차가 아니다. 원고에는 반드시 이 구분을 유지한 채 서술할 것.
